# 并查集

并查集维护一组互不相交的集合，支持两种基本操作：`find(x)` 找到元素所属集合的根，`union(a, b)` 把两个集合合并。每个元素只保存一个父指针 `parent[x]`，根节点指向自己；再从根出发记录一个 `rank`，合并时把较矮的树挂到较高的树下，避免树退化成链。查找时把路径上的节点直接接到根上，这就是**路径压缩**。两种优化一起使用时，单次操作的均摊复杂度接近 `O(1)`，严格写作 `O(α(n))`。

## 核心思路

并查集不保存整棵树的边，只给每个元素保存一个 `parent` 指针：

- `parent[x] = x` 表示 x 是根；否则沿 `parent[x]` 一路向上，最终到达的节点就是 x 所属集合的根。
- `find(x)` 从 x 出发向上走到根并返回；同时可以把路径上的节点直接挂到根上，这就是路径压缩。
- `union(a, b)` 先分别找到 a、b 的根；根相同说明已经在同一个集合，结构不变；根不同就把一棵树挂到另一棵树下。
- 按秩合并：比较两个根的 `rank`，把 rank 小的根挂到 rank 大的根下；只有 rank 相等时才让新根的 rank 加一，树高因此保持在 `O(log n)`。
- 输入中的每个 `{}` 只说明“这些元素属于同一个集合”，并不指定父子关系；组内再按按秩合并建出一棵平衡的树。

## 复杂度

设元素数为 n，树高为 h。

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| `find`（只用父指针） | O(h)，最坏 O(n) | 链状树每一步只向上走一层 |
| `find`（按秩合并 + 路径压缩） | 均摊 O(α(n)) | α(n) 增长极慢，可近似看作 O(1) |
| `union` | 两次 `find` + O(1) | 找到根后只改一个父指针 |
| `connected` | 两次 `find` | 比较两个根是否相同 |
| 创建 | O(n log n) 最坏 | 初始化 n 个元素，组内共做 n - k 次按秩合并 |
| 空间 | O(n) | 保存 `parent` 与 `rank` 两个数组 |

## 易错点

- 根的条件是 `parent[x] == x`，不是 `parent[x] == 0`；根可以不是 0，甚至可以是任意元素值。
- 路径压缩只改路径上节点的 `parent`，不会改变 `rank`。压缩后 rank 可能大于真实高度，但它仍是树高的上界，按秩合并依然正确。
- 按秩合并的方向不能反：应当把 rank 小的根挂到 rank 大的根下；只有两个 rank 相等时，才让新根的 rank 加一。
- `union(a, b)` 只修改被挂接的那个根的 `parent`，不要逐个修改集合里的元素。
- 两个元素已经同根时，`union` 不产生结构变化；本演示只发比较帧，不发挂接帧。
- `find` 和 `connected` 也会执行路径压缩，因此即使没有合并，`parent` 数组也可能发生变化。
- 元素值不要求从 0 开始：内部会先把元素值映射为节点 id，再用 id 访问 `parent` 和 `rank`；不要把元素值直接当下标。

## 输入格式

输入用 `{}` 划分集合，组内元素用逗号或空白分隔：

```text
{0,1,2,3}, {4,5}, {6,7}
```

- `{}` 只说明哪些元素属于同一个集合，不指定父指针。
- 组内按出现顺序**成对合并**，每次使用按秩合并，得到一棵平衡的树。
- 元素是 `-999` 到 `999` 的整数，最多 15 个。
- 不同集合不能包含相同元素；空组、组外字符、非整数都视为错误。
- 解析时在组之间写入 `NaN` 哨兵，`TraceInput.values` 仍然是 `number[]`。

默认输入：

```text
{0,1,2,3}, {4,5}, {6,7}
```

组内建树过程：

```text
{0,1,2,3}
先合并 0-1：1 → 0，rank[0] = 1
再合并 2-3：3 → 2，rank[2] = 1
最后合并 0-2：2 → 0，rank[0] = 2

      0
     / \
    1   2
        |
        3
```

默认创建后的状态：

```text
parent: [0, 0, 0, 2, 4, 4, 6, 6]
rank:   [2, 0, 1, 0, 1, 0, 1, 0]
```

常见错误：

| 情况 | 提示 |
| --- | --- |
| 空输入 | 请输入集合，例如 `{0,1,2}, {3,4}`。 |
| 没有使用 `{}` | 请用 `{}` 划分集合，例如 `{0,1,2}, {3,4}`。 |
| 空组 | 集合不能为空。 |
| 非整数或越界 | 请输入最多 15 个整数，范围 -999 到 999。 |
| 元素跨组重复 | 元素 3 重复出现，集合之间不能重叠。 |
| 超过 15 个元素 | 最多展示 15 个元素，请减小输入规模。 |
| 目标元素不在输入中 | 元素 3 不在集合中。 |

## 默认结果

默认操作是「查找」，元素 a 为 `3`；合并与连通的元素 b 为 `7`。

| 操作 | 路径 / 结果 | 帧数 |
| --- | --- | --- |
| 创建 | 初始化后，组内每次合并依次查找两个根、比较 rank、挂接 | 21 |
| 查找 3 | `3 → 2 → 0`，找到根 0 后把 `parent[3]` 改为 0 | 5 |
| 合并 3、7 | 查找 3（压缩）、查找 7、比较 rank 2 / 1、把根 6 挂到根 0 下 | 9 |
| 连通 3、7 | 查找 3、查找 7，根分别为 0 / 6，不连通 | 8 |

创建最后一帧的 `parent` 为 `[0, 0, 0, 2, 4, 4, 6, 6]`，`rank` 为 `[2, 0, 1, 0, 1, 0, 1, 0]`。

查找 3 后：

```text
parent: [0, 0, 0, 0, 4, 4, 6, 6]
rank:   [2, 0, 1, 0, 1, 0, 1, 0]
```

合并 3 与 7 后：

```text
parent: [0, 0, 0, 0, 4, 4, 0, 6]
rank:   [2, 0, 1, 0, 1, 0, 1, 0]
```

## 帧模型

- **创建**：先发初始化帧，所有元素各自成根；随后每个集合内部按成对合并的顺序，依次发查找根、比较 rank 与挂接帧。
- **查找**：准备帧、路径访问帧、找到根帧、路径压缩帧；已经直接指向根的节点不重复发压缩帧。
- **合并**：准备帧、两次查找（包含各自的路径压缩）、比较两个根、挂接帧；两个元素同根时只发比较帧，不发挂接帧。
- **连通**：准备帧、两次查找、答案帧；只查询，不合并。
- 最后一帧直接追加结果旁白，不单独增加完成帧。
- 每帧包含元素、父指针、rank、连线、当前节点、已访问路径、旁白和代码锚点；调用栈和队列为空。
- 切换操作或应用新输入后回到第 0 帧。

## 四种操作

### 创建

输入中的每个 `{}` 先拆成元素列表，再按下面的方式折叠：

```text
build_group(group):
    if len(group) == 1:
        return group[0]
    mid = len(group) // 2
    a = build_group(group[:mid])
    b = build_group(group[mid:])
    return unite(a, b)
```

`unite` 使用按秩合并。默认输入的分组顺序：

```text
{0,1,2,3}：合并 0-1，合并 2-3，再合并两个根
{4,5}：合并 4-5
{6,7}：合并 6-7
```

- 初始化帧锚点 `init`，旁白：`初始化：n 个元素各自成为一个集合。`
- 查找根帧锚点 `root`，旁白：`元素 X 的根是 R。`
- 比较帧锚点 `compare`，旁白说明两个根及 rank 关系。
- 挂接帧锚点 `link`，旁白：`把根 B 挂到根 A 下，rank[A] = r。`
- 最后一帧追加：`创建完成：共 n 个元素、k 个集合。`

### 查找

```text
find(x):
    root = x
    while parent[root] != root:
        root = parent[root]
    while parent[x] != root:
        next = parent[x]
        parent[x] = root
        x = next
    return root
```

- 准备帧锚点 `start`，旁白：`准备查找 X：从 X 开始沿父指针上溯。`
- 路径帧锚点 `visit`，旁白：`X 的父节点是 Y，继续上溯。`
- 根帧锚点 `root`，旁白：`找到根 R，路径为 A → B → R。`
- 压缩帧锚点 `compress`，旁白：`路径压缩：parent[X] = R。`
- 最后一帧追加：`查找完成：X 的根是 R。`
- 查找 3 的帧：`start`、`visit(3)`、`visit(2)`、`root(0)`、`compress(3)`。节点 2 已经直接指向根，不再重复压缩。

### 合并

```text
unite(a, b):
    ra = find(a)
    rb = find(b)
    if ra == rb:
        return ra
    if rank[ra] < rank[rb]:
        swap(ra, rb)
    parent[rb] = ra
    if rank[ra] == rank[rb]:
        rank[ra] += 1
    return ra
```

- 准备帧锚点 `start`，旁白：`准备合并 A 与 B：先查找两个根。`
- 两次查找产生的帧与「查找」操作相同，包含 `visit`、`root`、`compress`。
- 比较帧锚点 `compare`：说明两个根是否相同；rank 不同时指出哪棵树更矮，rank 相同时说明挂接后加一。
- 挂接帧锚点 `link`，旁白：`parent[根B] = 根A，rank[根A] = r。`
- 最后一帧追加：`合并完成：A 与 B 连通，根为 R。`
- 两个元素已经同根时，最后一帧追加：`合并完成：A 与 B 已连通，根为 R。`
- 默认合并 3、7：根 0 的 rank 为 2，根 6 的 rank 为 1，把 6 挂到 0 下，rank 不变。

### 连通

```text
connected(a, b):
    return find(a) == find(b)
```

- 准备帧锚点 `start`，旁白：`准备判断 A 与 B 是否连通：分别查找根。`
- 两次查找同样产生 `visit`、`root`、`compress` 帧。
- 答案帧锚点 `answer`，旁白：`A 的根是 RA，B 的根是 RB：连通 / 不连通。`
- 最后一帧追加：`连通性判断完成：A 与 B 连通。` 或 `... 不连通。`
- 连通查询会执行路径压缩，因此数组可能发生变化，但不会合并两个集合。

## 布局与边界

- 上半部分是森林：节点为圆形，直径 28；边从孩子顶边中点指向父节点底边中点，带箭头。
- 根节点按元素 id 顺序从左到右排列，子树按叶子槽位展开；同一集合的节点聚在一起。
- 森林的纵向层数按整段 trace 的最大元素数预留，默认 8 个元素最多 3 层，节点不重叠。
- 下半部分是两行数组：`parent` 行高 22，`rank` 行高 18；每列宽 30、间距 3，列头显示元素值。
- `parent` 行显示父元素值，根格显示自身；`rank` 行显示秩。
- 舞台高度固定为 208；默认 8 个元素时宽度 430，15 个元素时宽度 572，超出可用宽度时横向滚动。
- 路径压缩后节点沿轨迹移动到新父节点下；数组格同步显示新的父元素。
- 所有元素从初始化帧开始就存在，创建过程中只有父指针和位置变化，没有节点增删。

## 边界与测试

- 单集合、单元素：初始化后直接查找，根就是自身。
- 单集合、两个元素：查找任一元素只访问一层。
- 多集合：默认数据的三个根为 0、4、6。
- 长路径压缩：三元素链 `3 → 2 → 0`，压缩后 3、2 都直接指向 0。
- 合并同集合：不发 `link`，结构和 rank 不变。
- rank 相等时挂接：右根挂到左根下，左根 rank 加一。
- 连通查询：同根返回连通，异根返回不连通，查询后路径被压缩。
- 15 个元素、15 个单元素集合的初始化帧不重叠；15 个元素时宽度 572。
- 空输入、缺少 `{}`、空组、重复元素、非法值、目标元素不存在、超过 15 个元素。
- 每个操作每一帧的锚点都必须在六种语言模板中存在；代码显示文本不能残留 `@anchor`。
- 场景几何测试覆盖节点、数组列不碰撞，父指针箭头端点正确，根节点与数组格颜色同步，以及所有帧尺寸稳定。

## 实现约定

- 元素按首次出现顺序分配节点 id，从 0 开始；`items` 按 id 升序排列。
- `unionParents` 与 `unionRanks` 按 `items` 顺序存储；`unionParents[i]` 是父节点的 id，根节点指向自己。
- `links` 使用 **孩子 id → 父 id**，不包含自环；`active` / `settled` 仍是 `items` 下标。
- 根节点由 `unionParents[i] === items[i].id` 判定；不设置 `rootId`（并查集有多个根）。
- 每帧的 `variables` 至少包含 `size`（元素数）和 `sets`（当前根数）。
- 操作 `create`、`find`、`union`、`connected` 与代码模板键一致。
- 解析后的 `values` 用 `NaN` 分隔集合；直接调用 trace 时如果没有哨兵，整段视为一个集合。
